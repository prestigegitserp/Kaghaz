# کاغذ ۲ — جنس را از نزدیک ببینید

راستهٔ تعاملی فارسی با مدل‌های اختصاصی Blender، مصالح PBR و کاتالوگ قابل توسعه.

| نسخه | سایت | کد |
|---|---|---|
| نسخهٔ اول، محفوظ | [باز کردن v1](https://prestigegitserp.github.io/Kaghaz/v1/) | شاخهٔ `v1`؛ commit ثابت `25dc79f755cdd5f71b324f3f1705c67097421453` |
| نسخهٔ دوم | [باز کردن v2](https://prestigegitserp.github.io/Kaghaz/v2/) | شاخهٔ `v2` |
| آدرس قبلی | [ورودی اصلی](https://prestigegitserp.github.io/Kaghaz/) | همان نسخهٔ اول |

## چه چیز در v2 اضافه شده است؟

- **۹ مدل واقعی فایل GLB ساخته‌شده با Blender 4.3.2**: بند A4، بند ورق تسمه‌دار، پالت، کارتن باز و بسته، رول توخالی با ورق آزاد، بادبزن نمونه‌رنگ، دفتر جلددار و پیشخوان. تناسب‌ها متری هستند. رول مقطع حلقوی دارد؛ کارتن دیواره و زبانهٔ جدا؛ بند لفاف و بلوک کاغذ جدا دارد.
- **شش مجموعهٔ مصالح** کاغذ، کرافت، گردو، گچ، سنگ و آجر؛ نقشهٔ رنگ، زبری و normal مستقل. UV آجر روی ستون‌ها بر اساس متر تنظیم می‌شود.
- استودیوی چرخش و زوم از **همان مدل‌های داخل بازار** استفاده می‌کند. باز کردن اجزا، لفاف یا زبانه را از بدنه جدا می‌کند؛ سه حالت نور برای بررسی جنس وجود دارد.
- نور روز، عصر گرم و نور خنثی در بازار؛ محیط انعکاس برای PBR، سایهٔ ثابت و SSAO در کیفیت بالا.
- بازدید راهنما در چهار ایستگاه، مقایسهٔ مشخصات تا سه کالا، گالری سه رندر واقعی Cycles از صحنهٔ تألیف‌شده.
- اگر WebGL2 در دسترس نباشد، تصاویر واقعی Blender با برچسب «تصویر ثابت» نمایش داده می‌شوند. کاتالوگ، جست‌وجو، مقایسه، استعلام و ساخت غرفه ادامه دارند.
- ۸ غرفه و ۲۴ کالای نمونه؛ دو جایگاه غرفهٔ شخصی، تا ۴۰ کالای شخصی، ورود فایل GLB و PDF، علاقه‌مندی و استعلام محلی نسخهٔ اول حفظ شده‌اند.
- داده و فایل‌های شخصی `v2` در فضای جداگانهٔ مرورگر ذخیره می‌شوند. اطلاعات `v1` بازنویسی نمی‌شود. فایل JSON نسخهٔ اول را می‌توان دستی وارد نسخهٔ دوم کرد؛ فایل‌های GLB و PDF باید دوباره انتخاب شوند.

این صحنه، طراحی الهام‌گرفته از بازار است؛ اسکن اندازه‌برداری‌شدهٔ بهارستان نیست. مدل استودیو خانوادهٔ جنس را نمایش می‌دهد، نه مدل اختصاصی هر SKU یا تطبیق دقیق ابعاد و رنگ سفارش.

## سرعت و مرز بررسی

هندسهٔ خروجی بدون کاهش دقت، با تصاویر embedded WebP بسته‌بندی شده است. اندازه، SHA-256 و تعداد مثلث واقعی هر دارایی در [`asset-manifest.json`](public/v2/asset-manifest.json) ثبت می‌شود. مجموع انتقال مدل‌ها کمتر از ۶ MiB است؛ اندازهٔ انتقال با مصرف VRAM یکسان نیست.

بارگیری جزئیات نزدیک با صف دو درخواست هم‌زمان و cache مشترک انجام می‌شود. مدل‌های تکراری در هر غرفه instance می‌شوند؛ دورتر، نمایش هندسی سبک باقی می‌ماند. در سکون، رندر پیوسته متوقف می‌شود؛ حالت کیفیت خودکار با اندازه‌گیری کار CPU کیفیت را کاهش می‌دهد. این عدد **FPS یا زمان GPU نیست**.

رندرهای Blender روی CPU واقعاً تولید و بازبینی شده‌اند. محدودیت WebGL مرورگر ابری همچنان برقرار است؛ کارکرد بصری WebGL و نرخ فریم RTX 3060 لپ‌تاپ در این محیط اندازه‌گیری نشده‌اند. [گزارش اعتبارسنجی](docs/VALIDATION_V2.md) و [پذیرش نسخهٔ دوم](docs/V2_ASSETS_FA.md) را ببینید.

## اجرا و ساخت

Node.js 22.18+؛ نسخهٔ CI برابر Node 24 است.

```bash
npm ci
npm run dev
npm test
VITE_PUBLIC_BASE=/Kaghaz/v2/ npm run build
```

`dist/` خروجی ایستا است. هیچ CDN در مسیر اجرای مدل‌ها، رمزگشاها و فونت‌ها لازم نیست. GitHub Pages سرور دادهٔ فروشندگان نیست؛ داده‌های شخصی این نمونه در مرورگر می‌مانند.

## تولید دوبارهٔ دارایی‌ها

Python همراه Pillow و NumPy و Blender 4.3+ لازم است. نصب این ابزارها برای دیدن سایت لازم نیست.

```bash
python tools/assets/make_materials.py
blender --background --threads 6 --python tools/assets/build_assets.py
python tools/assets/pack_glb.py
npm test
```

فایل مؤلفهٔ Blender در `.asset-build/kaghaz-v2-authoring.blend` ذخیره می‌شود. کد ساخت مدل، مصالح، camera و نور همراه مخزن است؛ تصاویر خروجی WebP و GLBهای آماده نیز commit شده‌اند. بازتولید رندر CPU ممکن است چند دقیقه طول بکشد.

## انتشار دو نسخه

گردش‌کار Pages **روی `main`**، نسخهٔ اول را از commit ثابت و نسخهٔ دوم را از `v2` می‌سازد و یک artifact با سه مسیر می‌فرستد. پایان موفق `Validate Kaghaz v2` انتشار نسخهٔ دوم را فعال می‌کند؛ یک Pages deployment نمی‌تواند هم‌زمان دو شاخه را جداگانه به ریشه منتشر کند. به همین دلیل انتشار مرکزی است. تغییر مستقیم شاخهٔ `v1` برای توسعه لازم نیست.

## توسعه برای غرفه و اسکن

دادهٔ محصول در `src/domain`، جایگاه و برخورد در `booths.ts`، قرارداد دارایی در `asset-registry.ts` و بارگیری/cache در `authored.ts` جدا هستند. شناسهٔ کالا به نام مش یا ترتیب مثلث وابسته نیست. GLB شخصی هنوز به‌عنوان شیء در گوشهٔ غرفه جاگذاری می‌شود؛ جایگزینی کامل معماری با اسکن مغازه، آپلود عمومی، حساب فروشنده و همگام‌سازی موجودی به مرحلهٔ سروری نیاز دارند. این قابلیت‌ها در این نمونه وانمود نشده‌اند.
