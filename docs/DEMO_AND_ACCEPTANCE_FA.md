# ارائه، معیار پذیرش و توسعهٔ قراردادی

## قبل از قرار با مشتری

ابتدا روی دستگاهی که به جلسه می‌برید `npm ci`، `npm run build` و `npm run preview` اجرا کنید. به‌جای وابستگی به اینترنت جلسه می‌توان خروجی ایستا را روی لپ‌تاپ سرو کرد. آدرس خصوصی تحویل‌شده فقط برای صاحب سایت است؛ از قبل مسیر دسترسی مشتری را مشخص کنید.

در این محیط تست بصری مرورگر تأیید نشده است. بنابراین **قبل از ارائه، خودتان صحنه را ببینید** و چک‌لیست زیر را انجام دهید. این توصیه بر مبنای یک مانع واقعی بررسی است، نه تضمین ضمنی کیفیت.

سه کار را تمرین کنید: رفتن به سرای سپید، بازکردن کاغذ A4 و ساخت یک غرفهٔ شخصی. اگر فایل GLB اختصاصی ندارید، واردکردن مدل را در ارائه قولِ انجام‌شده ندهید؛ همان مسیر آمادهٔ دریافت را نشان دهید. هیچ اسم نمونه‌ای را شریک تجاری واقعی معرفی نکنید.

## چک‌لیست تصویری؛ هنوز باید روی دستگاه هدف اجرا شود

- از دور بپرسید «این چه بازاری است؟» اگر پاسخ صاحب صنف کاغذ و چاپ نبود، قاب شروع یا سهم انواع کالا باید عوض شود.
- بند کاغذ، کارتن، پالت و رول در یک قاب دیده شوند؛ اندازه و تفاوت آن‌ها بررسی شود.
- تابلوهای فارسی خوانا، بدون جابه‌جایی و وارونگی باشند. کوچک‌بودن نوشته روی تصویر لپ‌تاپ با نمایشگر بزرگ فرق دارد.
- اشیا روی زمین و میز قرار بگیرند؛ تماس، سایه، نسبت ارتفاع چشم و ارتفاع پیشخوان بررسی شود.
- صحنهٔ کم‌کیفیت هم باید هویت کاغذ را حفظ کند؛ حذف جزئیات نباید همه‌چیز را به حجم مبهم تبدیل کند.
- با تغییر زاویه، پشت مدل‌ها، درز سقف، نشت نور، clipping، z-fighting و تکرار بافت بررسی شود.
- روی موبایل عنوان و کنترل‌ها مانع دید نباشند؛ دکمهٔ جهت و نگاه هم‌زمان آزموده شوند.

## معیار عملکرد پیشنهادی برای قرارداد

اعداد زیر **هدف مذاکره و آزمون‌اند، نتیجهٔ اندازه‌گیری این نسخه نیستند**. دستگاه، مرورگر، شبکه، کیفیت و مسیر آزمون باید کنار عدد نوشته شود.

| شاخص | هدف اولیهٔ قابل مذاکره |
|---|---|
| رابط قابل استفاده | در چند ثانیهٔ اول روی اتصال توافق‌شده |
| تجربهٔ حرکت دسکتاپ متوسط | هدف ۵۰ تا ۶۰ فریم؛ با زمان فریم پایدار |
| موبایل متوسط در کیفیت سبک | هدف نزدیک ۳۰ فریم، بدون توقف طولانی |
| صحنهٔ ساکن | توقف درخواست‌های پیوستهٔ رندر پس از پایان حرکت |
| اولین دارایی‌های بازار | بودجهٔ مستقل از فایل‌های اسکن اضافه‌شده؛ حجم gzip و بافت جدا ثبت شود |
| مدل واردشده | زیر سقف قرارداد ورودی، با زمان decode و حافظهٔ ثبت‌شده |
| ورود به بخش جدید | بدون وقفهٔ شدید ناشی از compile یا decode در لحظهٔ تعامل |

آمار F3 در نسخهٔ اول تعداد draw، مثلث، DPR و **زمان CPU مربوط به فراخوانی فریم** را نشان می‌دهد. این عدد GPU time یا FPS واقعی نیست. برای ارزیابی GPU و فریم‌های افتاده، ابزار profiling مرورگر روی دستگاه هدف لازم است. نباید از معکوس زمان CPU به‌عنوان «FPS تضمینی» استفاده شود.

## مرزبندی پیشنهاد پروژه

مرحلهٔ اول قرارداد: یک مغازهٔ مرجع با محصولات و ظاهر تأییدشده، روی دو دستگاه توافق‌شده. مرحلهٔ دوم: حساب فروشنده و API کاتالوگ و استعلام. مرحلهٔ سوم: توسعه به تعداد مشخص مغازه و خط تولید دارایی و اسکن. هزینه و معیار پذیرش هر مرحله جداست.

این ترتیب کمک می‌کند جلسه بر یک خروجی محدود و قابل ارزیابی تکیه کند. درخواست از مشتری بهتر است «یک مغازهٔ مرجع و دسترسی به چند محصول واقعی برای پایلوت» باشد، سپس دربارهٔ بازار بزرگ‌تر تصمیم گرفته شود.
